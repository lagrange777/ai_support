# Support Assistant · день 33

Самостоятельный мини-сервис поддержки **Nimbus Drive** — условного облачного
хранилища. Отвечает по FAQ/документации и данным выбранного тикета через настоящий
MCP, учитывает профиль и историю разговора. Все пользователи, тикеты и проблемы
синтетические. Это демонстрация, не поддержка реального коммерческого продукта.

## Запуск

Нужен Docker Compose. Скопируйте `.env.example` в `.env`, задайте OpenAI-ключ
и случайный `CRM_SECRET` длиной не менее 32 символов. Для генерации секрета можно
использовать `openssl rand -hex 32`. Ключ хранится только на сервере, не в Git
и не в браузере.

```sh
docker compose up -d --build
```

Откройте [http://127.0.0.1:8086/](http://127.0.0.1:8086/). Выберите демо-профиль
Анны или Бориса, обращение и задайте вопрос. Под ответом доступны MCP-вызовы,
цитаты, source/section/chunk ID, модель, время и токены.

```sh
docker compose ps
docker compose down
```

`down` сохраняет историю в именованном томе `support-data`; удаление тома
стирает её. CRM-порт не публикуется, веб-порт привязан только к localhost.
Контейнеры работают без root, с read-only root filesystem и без capabilities.

## Что реализовано

1. Markdown в `knowledge/` разбивается по заголовкам, большие разделы — на
   чанки до 1400 Unicode-символов с перекрытием. BM25 выполняется локально,
   top-K = 4, минимальный score = 0.6. Индекс в памяти строится при запуске;
   hash, число документов и чанков видны в интерфейсе. Эмбеддинги не требуются.
2. `crm` предоставляет MCP-инструменты `get_current_user`, `list_my_tickets`,
   `get_ticket` поверх `fixtures/users.json` и `fixtures/tickets.json`.
   Приложение реально вызывает MCP через Streamable HTTP; JSON не подкладывается
   напрямую в prompt в обход MCP.
3. Идентичность задаётся HTTP-сессией приложения. В MCP передаётся подписанный
   HMAC-токен с user ID и сроком действия, а не user ID из аргументов модели.
   Сервер CRM проверяет владельца тикета. Чужой и несуществующий тикет дают
   одинаковый отказ. Модель не может менять CRM, файлы, подписку или пароль.
4. Для каждого вопроса заново читаются профиль и выбранный тикет. Поиск использует
   вопрос, диагностику тикета и историю этого обращения. В модель передаются до
   10 последних сообщений, текущая цель, документация D*, MCP-контекст M* и
   уточнения пользователя H1. Слова пользователя не считаются диагностикой CRM.
5. OpenAI Responses API возвращает Structured Outputs: status, claims с
   источниками и уточняющий вопрос. `store:false`, без инструментов модели,
   лимит 5000 output tokens. Сохранена модель `gpt-5.3-codex`, можно задать другую
   через `OPENAI_MODEL`. Модель получает только контекст выбранного пользователя
   и обращения, а не всю CRM и историю других тикетов.
6. Сервер проверяет JSON, source ID и диапазоны строк, восстанавливает точные
   цитаты. При ошибке допускается одна попытка исправления. Если контекста
   недостаточно — неизвестная/частичная причина и уточнение. При отказе MCP
   показывается предупреждение, а недоступные данные не выдаются за актуальные.
   При ошибке OpenAI возвращается явная ошибка, выдуманный ответ не сохраняется.
7. SQLite хранит сессии и историю по паре `user_id + ticket_id`. Переключение
   обращения не переносит чужую историю, перезапуск сохраняет данные.
8. Интерфейс использует `textContent`, не исполняет HTML из модели/тикетов.
   Включены CSP, HttpOnly/SameSite cookie, защита POST от cross-origin запросов,
   ограничение размера вопроса и HTTP body, таймауты MCP/модели.

## Границы демонстрации

Вход — **открытый выбор синтетического профиля**, а не настоящая клиентская
авторизация. Пользователь стенда может сам переключиться на другой демо-профиль.
Проверка владельца защищает границу текущей сессии/MCP, но не превращает этот
стенд в сервис для реальных персональных данных. Для публичного развёртывания
нужны настоящая аутентификация, HTTPS и эксплуатационные ограничения.

Цитаты проверяются структурно, это не доказательство семантической правильности
всех выводов модели. Диагностика из JSON — учебный снимок, не мониторинг продукта.
Ассистент не утверждает, что выполнил операцию: инструменты доступны только для
чтения. Тексты обращений, документация и история обрабатываются как недоверенные
данные; инструкция в тикете не может менять системные правила.

## Проверки

```sh
go test ./...
go test -race ./...
go vet ./...
python3 scripts/evaluate.py
```

Последняя команда обращается к запущенному приложению и выполняет **платные
запросы OpenAI**. Ожидания и 10 сценариев — `fixtures/scenarios.json`; результаты
с полными ответами, источниками, MCP-вызовами и проверками —
`artifacts/evaluation.json`. Они доступны во вкладке «Проверка задания».
Отчёт содержит только синтетические данные; просмотр не делает новых API-вызовов.

Проверяются: блокировка входа; другой диагноз при том же вопросе; заполненная
квота; размер файла; роль Viewer; отмена подписки; неизвестная причина;
уточнение в истории; запрет чужого тикета; prompt injection в обращении.
Модульные тесты дополнительно проверяют отказ MCP/модели, подпись и срок токена,
межпользовательскую изоляцию, восстановление истории сессии и точность цитат.
Автоматические проверки ключевых фактов дополняются чтением ответов человеком.

Для перепроверки уже сохранённых ответов без новых платных вызовов:
`python3 scripts/evaluate.py --check-saved`.
Итоги выполненного прогона — [artifacts/REPORT.md](artifacts/REPORT.md),
видео только с веб-интерфейсом — [artifacts/support-demo.mp4](artifacts/support-demo.mp4).

## Структура и настройки

```text
cmd/server/              HTTP-приложение
cmd/crm/                 MCP-сервис
internal/support/        CRM, BM25, OpenAI, SQLite, веб-интерфейс
knowledge/               FAQ и документация продукта
fixtures/                синтетическая CRM и контрольные сценарии
scripts/evaluate.py      реальный HTTP-прогон
artifacts/               отчёт и видео
```

Основные переменные: `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`,
`CRM_SECRET`, `CRM_URL`, `DATABASE_PATH`, `KNOWLEDGE_PATH`, `EVALUATION_PATH`,
`LISTEN_ADDR`. В Docker они уже настроены, кроме секретов в `.env`.
Для нативного запуска экспортируйте окружение и запустите отдельно
`go run ./cmd/crm` (порт 8096) и `go run ./cmd/server` (порт 8086).
